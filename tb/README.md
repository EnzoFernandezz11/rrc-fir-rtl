# Testbenches

Cada variante RTL necesita un testbench que devuelva código de error (`$fatal`) si falla una comparación. El banco común futuro leerá los vectores deterministas de `vectors/`, alineará salidas por índice válido y reportará I/Q esperado y obtenido. Las reglas numéricas se fijan en el [contrato de verificación](../docs/contratos/verificacion-y-ppa.md).

`frequency/tb_fir_frequency_serial.sv` verifica los formatos A04: entrada 2/0, work 12/5, H/W 10/8 y salida 9/7, con redondeo mitad hacia arriba y sin saturación. `make smoke` genera `build/frequency_serial_vectors.txt` desde `model.fixed_point.fir_frequency_fxp` mediante `python3 -m scripts.frequency_serial_vectors`, y lo compara palabra por palabra con el RTL usando Icarus. Incluye casos A03 (ceros, impulsos, longitudes 0…40 y semillas), ventanas de peor caso A04, las cinco semillas de 1024 símbolos para SQNR, pausas, backpressure, reset y tiempos. La entrada soportada es I/Q en {−1, 0, +1}.

El banco también mantiene casos locales de protocolo con una referencia entera SystemVerilog y pruebas del multiplicador con signos/extremos, dos anchos de salida y redondeo de productos (incluidos empates negativos y límites de ancho). `vvp build/frequency_serial.out +dump_constants` muestra las tablas A04, una vez generados los vectores.

Además, C02 lee los cinco archivos oficiales [A05](../vectors/README.md) (426 muestras) y `build/vectors/qpsk_s1.txt` (2048 muestras), comparando exactamente con `yf_i/yf_q` y `last`. Cada archivo corre sin pausas y con burbujas/backpressure, sin reset entre las tramas del archivo. `make smoke` ejecuta `python3 -m model.vectors` para generarlos después de comprobar que los archivos versionados están al día. Se conservan `L = 559`, bloque completo de 575 ciclos e intervalo entre bloques de 568 ciclos.

Para diagnosticar un archivo A05 aislado: `vvp build/frequency_serial.out +a05_file=vectors/bordes.txt` lo ejecuta de ambos modos sin necesitar el archivo local A04. Un archivo ausente, vacío, con filas incompletas o columnas extra, índices discontinuos, valores desconocidos/fuera de rango, tramas mayores de 2048 muestras o una trama final sin `last` causa `$fatal` con archivo e índice. `python3 -m unittest tests.test_frequency_vectors -v` comprueba estos errores usando archivos temporales y verifica que la referencia sea la columna de frecuencia.

- `time/tb_fir_time_serial.sv` (B02): corre cada vector smoke dos veces, ideal (comprueba `L = 9` e `II = 10`) y con burbujas y `out_ready = 0` pseudoaleatorios (semilla 1), y compara contra `yt`. Con `vvp build/time_serial.out +regresion` agrega `build/vectors/qpsk_s1.txt`, que se genera con `python3 -m model.vectors`.

`frequency_optimized/tb_fir_frequency_optimized.sv` verifica la integración C04 contra el modelo fijo y los vectores A04/A05: 837 tramas, incluyendo pausas, backpressure y reset. La regresión pasó con L=26, II de muestra 1 e II de bloque 8. Las pruebas unitarias de CSD, producto complejo, FFT, espectral y escala están en `tests/`. La síntesis estructural Yosys pasó; el PPA físico queda pendiente de Vivado externo.
